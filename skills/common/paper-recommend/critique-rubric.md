# 摘要 / 锐评 / 对比 的写法规范

三段各有不同职责，不要互相串味：摘要只讲论文说了什么，锐评只讲你的判断，对比只讲它在用户已有阅读史里的位置。

## 一、摘要（`summary_zh`）

3-5 句，必须包含四件事，缺一不可：

1. **它要解决的具体问题**（不是领域背景）
2. **方法的核心机制**——具体到"怎么做的"，不是"提出了一个框架"
3. **实验规模**：数据集名称与量级、对比了谁
4. **关键数字**：主指标提升多少，从多少到多少

英文摘要里的自夸句（novel / significantly outperforms / extensive experiments）一律不译。

**反例**（信息量为零）：

> 本文提出了一种新颖的基于深度学习的 CAD 特征识别框架，通过引入注意力机制有效提升了识别精度，在多个数据集上的大量实验验证了方法的有效性。

**正例**：

> 针对 B-rep 模型上加工特征识别依赖人工标注的问题，用掩码自编码预训练替代监督训练：把面-边邻接图的部分节点属性遮盖，让模型重建面类型与邻接关系，再在下游用少量标注微调。在 MFCAD 与 MFInstSeg 上评测，标注量降到 10% 时面级 IoU 仍有 0.83，全监督基线在同等标注量下掉到 0.61。作者开源了预训练权重。

## 二、锐评（`critique_zh`）

150-350 字。**必须给出可被反驳的判断**——如果这段话换到任何一篇同领域论文上都成立，那它就是废话。

必须覆盖：

| 维度 | 要问的问题 |
|------|-----------|
| 真新意 | 是新机制，还是换 backbone / 换数据集 / 多加一个 loss？前人哪篇已经做过八成？ |
| 比较公平性 | baseline 是不是选的弱的、旧的？有没有在自己的设定上对比别人的默认配置？ |
| 实验支撑 | 主张有没有对应的 ablation？数据规模够不够撑起结论？换分布还成不成立？ |
| 可复现 | 代码/数据/权重是否开源？关键超参有没有交代？ |
| 落地意义 | 对提问者的实际用途意味着什么，卡在哪一步？ |

结尾必须有一句明确结论，三选一：**值得精读** / **只需知道结论** / **可以跳过**。

**落地视角**：当话题涉及 CAD、几何处理、工程图、公差、制造工艺时，直接对照 do_dimension 的实际场景说（能不能接进现有 pipeline、几何退化情况扛不扛得住、要不要标注数据、推理耗时是否可接受）。别泛泛谈"具有工业应用潜力"。

**禁止句式**（出现即重写）：

- 这是一项有前景/有意义/有价值的工作
- 具有重要的理论意义和应用价值
- 方法简洁有效
- 为该领域提供了新的思路
- 值得进一步研究
- 实验充分验证了方法的有效性

**反例**：

> 这篇工作思路清晰，方法简洁有效，实验较为充分，为 CAD 特征识别提供了新的思路，具有一定的工业应用潜力，值得进一步关注。

**正例**：

> 自监督这条路在 B-rep 上是对的，但这篇的新意被高估了：遮盖-重建的范式跟 BrepMFR 那套预训练几乎同构，真正的差别只是把重建目标从面类型换成了面类型+邻接，消融里也没把这两项拆开，所以"邻接重建带来增益"这个主张是没被验证的。baseline 选得偏软——只比了全监督的 UV-Net 和 Hierarchical CADNet，没比同期任何自监督方法，等于回避了最该比的对手。10% 标注下 IoU 0.83 这个数字本身可信，但 MFCAD 是合成数据，面数量级和真实钣金件差两个数量级，迁移到工业模型上基本要重训。对我们的用处在预训练思路而不是权重：do_dimension 的场景里孔/槽/折弯面的邻接结构远比合成数据脏，直接拿权重推理会崩，但"用邻接关系做自监督信号"这一点可以搬到已有的面聚类逻辑上。**只需知道结论**，权重不必下载。

## 三、与历史推荐的对比（`compare_zh`）

**必须基于 `similar` 的真实返回结果**，禁止凭印象编造历史论文。按 `similarity` 分三种写法：

### 相似度 > 0.15（实质同题）

指名历史论文的 `paper_id` 与标题，说清**哪个轴变了**（问题设定 / 方法机制 / 数据 / 评价指标），再判断是不是实质进步。要引用你当时给出的锐评并对照——如果当时的批评这次被解决了，明确说；没解决，也明确说。

> 与 `arxiv:2602.18296`（Context-Aware Mapping of 2D Drawing Annotations to 3D CAD Features，2026-08 推过，你打了 5 分）同题：都要在 2D 标注和 3D 面之间建立对应。差异轴只有一个——那篇用 LLM 做语义推理来消歧，这篇退回到几何投影+规则匹配。上次我批评那篇没给面级召回率，这篇给了（0.91），但代价是只支持轴对齐视图，斜视图直接不处理。所以不是那篇的进步版，而是它的一个更保守、可验证的子集。

### 相似度 0.04-0.15（同大方向不同分支）

说清共同的上位问题，以及两者在解法上的分岔点。

> 和历史库里 `doi:10.1016/j.compind.2021.103442`（从工程图抽取尺寸要求）共享"图纸信息数字化"这个上位问题，但方向相反：那篇从 2D 图纸往数据库走，这篇从 3D 模型往 2D 标注走。放在一起看的价值是它们的失败模式互补——前者栽在符号变体，后者栽在视图选择。

### 无相似结果

如实写，并说明它在库里开了什么新方向。禁止含糊地说"与之前推荐的论文类似"。

> 历史库中无相似论文（`similar` 最高 0.03），这是首次覆盖自监督预训练在 B-rep 上的应用。此前库里 CAD 方向全是监督学习与规则方法，这篇标记了一条新支线。

### 该篇本身推荐过

如果 `search` 结果里 `seen: true`，必须在对比里说明：上次什么时候推的、用户打了几分、这次为什么还要提（有新版本？被新工作反驳了？还是当时被低估了）。用户给过 1-2 分的论文，除非有强理由，不要再推。

### 作者重合（`shared_authors` 非空）

`similar` 的 `author_jaccard` / `shared_authors` 会独立报告作者重合，**文本相似度低也照样返回**。同一个组的连续工作是最强的追踪信号，遇到就必须在对比里点明，并判断这是版本迭代（`supersedes`）、能力扩展（`extends`）还是同组换赛道（只是 `same_group_as`）。

> 与 `arxiv:2408.06891` 是同一批人（Khan / Chen / Ng / Feng / Tan / Moon，6 位作者完全重合，`author_jaccard` 1.0，但文本相似度只有 0.07）。上一篇从 3D CAD 抽尺寸属性，这篇转向 2D 图纸的 VLM 抽取——不是迭代而是同组换赛道，说明这个组在赌「工程图信息抽取」这条线上下游都要占住。判断他们后续走向时，把两篇当一个连续的研究纲领看，比单独评估任一篇准。

### 对比要落成图谱边

写完对比这段，回头把里面陈述的关系落成 `relations` 字段（判定标准见 SKILL.md）。**只落写在对比里、有摘要或作者名单支撑的那些**——散文里说"两者互补"不构成一条边，摘要里点名"我们与 AAGNet 对比"才构成。对比段是给人读的，`relations` 是给图谱查的，两者内容必须一致，不能一边说是基线关系一边不落边。
